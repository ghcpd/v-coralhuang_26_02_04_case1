User: A parsing issue exists when using sqlglot to parse valid ClickHouse SQL involving tuple expressions with aliased elements and positional access.

The following SQL is valid and executes successfully in ClickHouse:

SELECT CAST(tuple(1 AS `a`, 2 AS `b`, 3.0 AS `c`).2 AS Nullable(String))

However, when parsed using sqlglot (e.g. version 14.0.0) with the ClickHouse dialect, the parser fails.

Reproduction snippet:

import sqlglot as sg

sg.parse_one(
    "SELECT CAST(tuple(1 AS `a`, 2 AS `b`, 3.0 AS `c`).2 AS Nullable(String))",
    read="clickhouse"
)

Task:
Update sqlglot so that this SQL can be parsed correctly under the ClickHouse dialect, and ensure the fix is covered by automated tests.

Functional requirements:
1. The ClickHouse dialect must correctly parse tuple() expressions whose arguments use aliases (e.g. "1 AS a", including backtick-quoted aliases).
2. Positional tuple access (e.g. ".2") must work in combination with such tuple expressions.
3. CAST targeting ClickHouse-specific types (e.g. Nullable(String)) must continue to work as before.
4. The change must not break parsing behavior for other dialects.

Design constraints:
- Do not hard-code special cases for the exact SQL string above.
- Prefer a solution that generalizes to similar “struct-like” functions that may accept aliased arguments.
- Keep parsing logic consistent with how the parser handles aliased arguments in other contexts.
- Avoid dialect-specific hacks unless strictly necessary.
- Ensure parse → serialize → parse round-trip correctness for ClickHouse.

## 💡 Design notes & rationale

- The parser change is not a special-case for the example SQL string. Instead, it generalizes parsing for struct-like tokens (`TokenType.STRUCT`) so that any function tokenized as a struct will accept aliased arguments (consistent with `STRUCT` parsing logic).
- This approach keeps the parser behavior consistent with existing handling of aliased struct arguments elsewhere (e.g., `_parse_struct`) and avoids dialect hacks or hard-coded strings.
- Trade-offs: alias parsing is now enabled for any function tokenized as `STRUCT`, which is consistent with semantics of struct-like functions. Other dialect parsing remains unaffected.
